# 小紅書圖文（Redbook）

把小紅書選題做成一套可發佈的圖文：封面、內頁、結尾圖、標題、正文、標籤。

## 何時使用

用戶明確要求小紅書圖文時：

- `/redbook`
- 「做小紅書圖文」
- 「小紅書配圖」
- 「幫我把這篇文章做成小紅書」

不適用：

- 只要一張封面圖
- 只要文案，不要圖
- 要發佈、留言、點讚、收藏

## 邊界（不可協商）

- **只出圖文**。不發佈、不留言、不點讚、不收藏、不存草稿。
- 不需要、也不接受小紅書 cookie。
- 用戶要求發佈時，說一句「這個設定不碰帳號」，並解釋風控風險，然後停止。
- 對話用繁體中文。**小紅書文案用簡體中文**。
- 不抄襲。研究只用來抽結構、角度、hook，不是複製內容。
- 醫療、投資、療效、保證性宣稱，一律不改寫成肯定句。

## 流程（不可跳步）

```
0 檢查登入 → 1 必問 → 2 研究 → 3 風格判斷 → 4 結構
→ 5 文案 → 6 逐頁 prompt → 7 出圖 → 8 自檢 → 9 交付
```

### 0. 檢查登入

```bash
export PATH="$HOME/.local/bin:$HOME/.composio:$PATH"
oo auth status
```

未登入就停止，叫用戶打 `/setup`。不要猜，也不要先做圖。

### 1. 必問（Mandatory ask）

**未答完，不可以生成任何圖片。**

一次問完，不要逐條盤問。需要的資料：

1. 主題是什麼？一句話。
2. 目的：漲粉、收藏、種草、帶貨、品牌、記錄？
3. 受眾：新手、上班族、媽媽、學生、創業者？
4. 語氣：乾貨、種草、故事、清單、吐槽、教學？
5. 風格：見下面五個 preset，選一個或給參考圖。
6. 頁數：默認 6 頁（簡單 2-3，中等 6-8，深度 9-10）。
7. 品牌元素：主色、logo、一定要出現或一定不可以出現的東西。
8. 有沒有對標帳號或參考筆記？

把答案寫入 `brief.md`。

### 2. 研究（RedFoxHub）

先講成本：「用 oo，約 4.06 點。」

```bash
# 找最熱的筆記
oo connector run redfox -a search_xiaohongshu_works \
  -d '{"keyword":"<關鍵詞>","sortType":"_4","exactMatch":false}'
```

參數：

- `sortType`：`_0` 相關性、`_2` 最新、`_4` 最熱
- `offset`：每頁 20，第二頁用 20
- `exactMatch`：`true` 只在關鍵詞是完整短語時用

做法：

- 看 5-10 篇高互動筆記。
- 記錄：標題句式、封面元素、痛點、收藏理由、留言高頻問題。
- 需要對標帳號時，用 `redfox.search_xiaohongshu_users`。
- 需要看單篇內容時，用 `redfox.get_xiaohongshu_work`。
- 寫入 `research.md`。不要貼大段原文。

如果研究失敗，說一句，然後用用戶給的 brief 繼續；不要假裝有研究。

### 3. 風格判斷

先判斷，後出圖。輸出：

- 主風格
- 輔助風格
- 不建議的風格，以及理由
- 三套方案：配色、字體、構圖、封面 hook
- 推薦哪一套，為什麼

五個 preset：

| Preset | 適合 | 配色 | 質感 |
|---|---|---|---|
| 奶油手繪 | 生活、育兒、感情 | 米白、淺粉、薄荷綠 | 手繪線條、貼紙、螢光筆 |
| 高級雜誌 | 商業、職場、觀點 | 黑、灰、白、一個亮色 | 大標、襯線、留白 |
| 科技極簡 | AI、工具、效率 | 深灰、黑、螢光綠 | 網格、數據、終端感 |
| 可愛貼紙 | 美食、旅遊、日常 | 高飽和、對比色 | emoji、對話泡、粗邊 |
| 知識卡片 | 教學、清單、乾貨 | 白底、單一重點色 | 編號、圖示、整齊 |

輸出 `style.md`，等用戶選一套才繼續。

### 4. 結構

默認 6-8 頁：

- **封面**：一個 hook + 主標。3 秒內讀得完。
- **內頁**：每頁一個觀點。3-5 行，最多 40 字。
- **結尾**：總結、行動、金句，或「收藏起來」。

輸出 `outline.md`，每頁寫：頁碼、角色、核心句、視覺元素。

### 5. 文案

用**簡體中文**寫入 `copy.md`：

- 標題：20 字內，帶數字、痛點或反差。
- 正文：300-600 字，短段，每段一個意思。
- emoji：少量，不超過 6 個。
- 標籤：5-8 個，混合大詞和小詞。
- 置頂評論：一句引導，例如「你最想先解決哪一個？」

不要用「姐妹們」「家人們」這類空泛稱呼，除非用戶要求。

### 6. 逐頁 prompt

每頁一個檔案：`prompts/01-cover.md`、`prompts/02-....md`。

每個 prompt 要有：

- 比例：3:4，1080×1440
- 風格：preset 的關鍵詞
- 版面：標題區、主視覺區、留白
- 配色：具體色名或 hex
- 主視覺：一個具體物件或場景
- 文字：只放 3-8 字短標；長文案留在正文
- 負面：`text artifacts, watermark, logo, blurry, extra fingers, cluttered`

不要在圖裡塞長句。Qwen 出中文字有機會出錯；生成後要檢查，錯字就重生一次。

### 7. 出圖（oo Qwen）

先講成本：「用 oo，每張約 6.18 點。」

先出封面一張，給用戶確認風格，再批量。

```bash
oo connector run qwen -a generate_image -d '{
  "model": "qwen-image-3.0",
  "prompt": "<逐頁 prompt>",
  "size": "1080*1440",
  "imageCount": 1,
  "negativePrompt": "text artifacts, watermark, logo, blurry, extra fingers, cluttered",
  "watermark": false
}'
```

規則：

- `size` 用 `1080*1440`（3:4）。
- 有參考圖時，先 `oo file upload <file>` 取公開 URL，放進 `images` 陣列，最多 3 張。
- 回傳的 `images` 是**臨時 URL**，即刻下載到 `images/`。
- 批量前先報總數和總點數，例如「6 張，約 37 點」。
- 超過 10 點要先問，等用戶同意才繼續。
- 風格跑掉時，固定同一段 style block 和 `seed`，只改主體。

### 8. 自檢

逐項檢查，寫入 `checklist.md`：

- 每頁只有一個觀點
- 封面 3 秒讀得完
- 內頁不超過 40 字
- 六頁的風格、字體、色調一致
- 沒有錯字，沒有繁簡混用（文案全簡體）
- 品牌元素正確
- 標題和封面 hook 對得上
- 沒有醫療、投資、療效保證

不合格就改，不要交出去。

### 9. 交付

輸出目錄：

```
redbook-{topic-slug}/
├── brief.md
├── research.md
├── style.md
├── outline.md
├── copy.md
├── checklist.md
├── prompts/
│   ├── 01-cover.md
│   └── ...
└── images/
    ├── 01-cover.png
    └── ...
```

回報：

- 主題、頁數
- 選了哪套風格
- 檔案位置
- 用了多少點（oo），實際數字如果回傳得到就報，否則說「未回傳」

### 可選：合併 PDF

用戶要求時才做：

```bash
oo connector run aisa -a convert_images_to_pdf -d '{"files":[...]}'
```

約 3.15 點。先報價。不要預設做。

## 成本

| 動作 | 平台 | 大約 |
|---|---|---|
| 小紅書研究，每次 | oo `redfox` | 4.06 點 |
| 生成一張圖 | oo `qwen` | 6.18 點 |
| 合併 PDF | oo `aisa` | 3.15 點 |

每次都要講「用 oo，約 X 點」。做完如果有用量就報，沒有就說未回傳。

## 失敗處理

- 未登入：`/setup`。
- 點數不足：報數字，停止。
- schema 錯：`oo connector schema qwen.generate_image`，改一次。
- 圖片 URL 過期：重新生成，或即時下載。
- 風格不一致：固定 style block + seed，重出一張對比。
- 研究失敗：說一句，用 brief 繼續。

## 不要做

- 不發佈、不互動、不存草稿
- 不用 cookie
- 不抄別人的筆記
- 不把長文案塞進圖
- 不在未答完問題前出圖
- 不假裝成功
